# Подключение сайта к базе Supabase и доступ в «Администрирование»

Раньше вход в админку открывался паролем, который лежал прямо в коде сайта — его мог посмотреть
любой посетитель. Теперь вход проверяется по базе данных **Supabase**: нужны почта и пароль
аккаунта, а право на доступ подтверждается записью в таблице `admins`.

---

## Шаг 1. Создайте проект в Supabase

1. Откройте <https://supabase.com> → **Sign in** (или зарегистрируйтесь) → **New project**.
2. Придумайте название проекта, пароль базы и выберите регион (ближе всего — `eu-central-1`).
3. Дождитесь, пока проект создастся (около минуты).

## Шаг 2. Скопируйте данные для подключения

1. В панели Supabase слева выберите **Project Settings** (шестерёнка) → **API**.
2. Скопируйте два значения:
   - **Project URL** — вида `https://abcdefghij.supabase.co`;
   - **anon / public** ключ — длинная строка, начинающаяся с `eyJ`.
3. Откройте файл `src/integrations/supabase/config.ts` и впишите значения:

```ts
export const SUPABASE_URL = "https://abcdefghij.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6...";
```

4. Сохраните файл и соберите сайт (`npm run build` или обычный push в GitHub).

> **Это не секрет?** Ключ `anon` публичный по замыслу Supabase: он зашит в сайт у всех проектов
> и не даёт доступа к данным без входа, потому что таблицы защищены политиками RLS.
> Секретные ключи (`service_role`) в код сайта вписывать **нельзя**.

## Шаг 3. Назначьте себя администратором

1. В Supabase слева выберите **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema.sql`, скопируйте его содержимое, замените в нём
   `you@example.com` на **свою почту** и вставьте в окно запроса.
3. Нажмите **Run** (Ctrl + Enter). Появится сообщение `Success`.

Теперь в базе есть таблица `admins` со строкой, в которой указана ваша почта.

## Шаг 4. Создайте аккаунт для входа

1. В Supabase слева выберите **Authentication** → **Users** → **Add user** → **Create new user**.
2. Впишите **ту же самую почту**, что вы указали в таблице `admins`, и придумайте пароль.
3. Поставьте галочку **Auto Confirm User** (чтобы не подтверждать почту письмом) → **Create user**.

## Шаг 5. Закройте регистрацию на сайте

1. В Supabase: **Authentication** → **Sign In / Providers** → **Email**.
2. Выключите **Allow new users to sign up** → **Save**.

Теперь аккаунт нельзя создать самому — только вы даёте доступ через панель Supabase.

## Шаг 6. Проверьте вход

1. Откройте сайт → `https://<ВАШ-ЛОГИН>.github.io/stroikacalc/#/admin`.
2. Введите почту и пароль аккаунта из шага 4.
3. Должна открыться панель «Администрирование», а вверху появиться ваша почта и роль.

---

## Как дать доступ ещё одному человеку

1. **Authentication** → **Users** → **Add user** → почта и пароль → **Auto Confirm User**.
2. **SQL Editor** — выполните:

```sql
insert into public.admins (email, role)
values ('pomoshnik@example.com', 'admin')
on conflict (email) do update set role = excluded.role;
```

Без записи в таблице `admins` аккаунт существует, но панель ему не откроется.

## Как забрать доступ

Удалите строку с почтой из таблицы `admins` (или удалите пользователя в **Authentication → Users**).
Вход перестанет работать сразу, даже если браузер запомнил сессию.

---

## Если что-то пошло не так

| Сообщение на экране входа | Причина и решение |
|---|---|
| «База данных Supabase не подключена» | В `src/integrations/supabase/config.ts` остались заглушки `YOUR-PROJECT`. Впишите Project URL и anon-ключ и соберите сайт заново. |
| «Неверная почта или пароль» | Проверьте данные аккаунта из **Authentication → Users**. |
| «Почта не подтверждена» | В **Authentication → Users** откройте аккаунт и нажмите **Confirm user**, либо создайте пользователя с галочкой **Auto Confirm User**. |
| «Этот аккаунт не входит в список администраторов» | Почта аккаунта не найдена в таблице `admins` — добавьте её (см. выше). |
| «Нет связи с базой данных» | Проверьте, что Project URL указан без лишних символов и заканчивается на `.supabase.co`. |
| Панель открылась, но вверху жёлтое предупреждение про таблицу `admins` | Скрипт `supabase/schema.sql` ещё не выполнялся — выполните его в SQL Editor. |

## Что ещё хранится в базе

Сейчас в Supabase живут только **вход и список администраторов**. Настройки сайта (бегущая строка,
меню, подвал) по-прежнему публикуются в Google-таблицу — как и раньше, из раздела
«Общие параметры сайта» в админке. Если хотите перенести и их в Supabase, напишите —
добавлю таблицу настроек и заменю синхронизацию.
